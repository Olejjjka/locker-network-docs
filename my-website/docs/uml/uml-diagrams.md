# UML-диаграммы

В данном разделе представлены UML-диаграммы, подготовленные для проекта **«Платформа городской сети камер хранения с возможностью доставки вещей между локациями»**.

В рамках артефакта используются:

- **Use Case diagram** – для описания основных акторов и вариантов использования системы;
- **Sequence diagram** – для описания сценария оформления перемещения вещи между локациями.

## Sequence diagram

Диаграмма последовательности описывает сценарий оформления заказа на перемещение вещи между камерами хранения.

Сценарий начинается с открытия пользователем раздела управления хранением, затем система получает данные текущего хранения, показывает доступные целевые локации, рассчитывает параметры перемещения и создаёт заказ. Сценарий оплаты вынесен за рамки диаграммы, так как платёжный контур описывается отдельно.

```plantuml
@startuml
skinparam style strictuml
skinparam SequenceMessageAlignment center
hide footbox
autonumber

actor "Пользователь" as User
participant "Веб-интерфейс" as Frontend
participant "Бэкенд платформы" as Backend
participant "Картографический сервис" as MapService
database "База данных" as DB
participant "Служба доставки" as DeliveryService

== Инициация процесса ==

User -> Frontend: Открывает "Управление хранением"
Frontend -> Backend: Запрос текущего состояния хранения
Backend -> DB: Получение информации о текущей ячейке
DB --> Backend: Данные бронирования
Backend --> Frontend: Информация о текущей ячейке
Frontend --> User: Отображение информации
User -> Frontend: Нажимает "Заказать перемещение"

== Выбор точки назначения ==

Frontend -> Backend: Запрос списка доступных камер
Backend -> DB: Получение доступных целевых локаций
DB --> Backend: Список доступных камер
Backend --> Frontend: Список камер с координатами
Frontend -> MapService: Запрос карты для визуализации
MapService --> Frontend: Данные карты
Frontend --> User: Отображение карты с доступными точками
User -> Frontend: Выбирает целевую камеру хранения

== Расчёт ==

Frontend -> Backend: Запрос расчёта перемещения
Backend -> Backend: Расчёт стоимости и времени
Backend --> Frontend: Стоимость и время перемещения
Frontend --> User: Отображение условий и кнопки "Оплатить"

== Подтверждение и создание заказа ==

User -> Frontend: Подтверждает и оплачивает заказ
note over Frontend, Backend: Сценарий оплаты вынесен за рамки диаграммы
Frontend -> Backend: Передача данных для создания заказа
Backend -> DB: Создание записи Transfer
DB --> Backend: Запись создана
Backend -> DeliveryService: Запрос на поиск курьера

== Результат назначения курьера ==

alt Курьер найден
    DeliveryService --> Backend: Курьер назначен
    Backend -> DB: Обновление статуса "COURIER_ASSIGNED"
    DB --> Backend: OK
    Backend --> Frontend: Подтверждение назначения курьера
    Frontend --> User: "Курьер назначен"
else Курьеры заняты
    DeliveryService --> Backend: Нет свободных курьеров
    Backend -> DB: Сохранение статуса "WAITING_FOR_COURIER_ASSIGNMENT"
    DB --> Backend: OK
    Backend --> Frontend: Статус ожидания назначения
    Frontend --> User: "Заказ ожидает назначения курьера"
end

@enduml
```

## Use Case diagram

Use Case-диаграмма показывает основные роли и пользовательские сценарии платформы.

В финальной упрощённой модели выделяются три основных актора:

- **Пользователь** – работает с хранением, перемещением, оплатой и поддержкой;
- **Курьер** – получает задание на перемещение и подтверждает выполнение этапов доставки;
- **Сотрудник поддержки** – обрабатывает обращения пользователей.

```plantuml
@startuml
left to right direction

actor "Пользователь" as User
actor "Курьер" as Courier
actor "Сотрудник\nподдержки" as Support

rectangle "Платформа городской сети камер хранения" {

    usecase "Поиск доступной\nячейки" as UC_Search
    usecase "Создание\nбронирования" as UC_CreateBooking
    usecase "Начало хранения" as UC_StartStorage
    usecase "Продление\nхранения" as UC_ExtendStorage
    usecase "Заказ перемещения\nвещей" as UC_Move
    usecase "Оплата услуг" as UC_Pay
    usecase "Отслеживание статуса\nперемещения" as UC_TrackMove
    usecase "Завершение\nхранения" as UC_Finish
    usecase "Отмена\nбронирования" as UC_CancelBooking
    usecase "Отмена заказа\nна перемещение" as UC_CancelMove
    usecase "Обращение в службу\nподдержки" as UC_Support

    usecase "Получение задания\nна перемещение" as UC_GetTask
    usecase "Подтверждение забора\nи доставки вещи" as UC_Deliver

    usecase "Обработка обращения" as UC_HandleSupport
}

User --> UC_Search
User --> UC_CreateBooking
User --> UC_StartStorage
User --> UC_ExtendStorage
User --> UC_Move
User --> UC_Pay
User --> UC_TrackMove
User --> UC_Finish
User --> UC_CancelBooking
User --> UC_CancelMove
User --> UC_Support

Courier --> UC_GetTask
Courier --> UC_Deliver

Support --> UC_HandleSupport

UC_CreateBooking ..> UC_Search : <<include>>
UC_Move ..> UC_Pay : <<include>>
UC_ExtendStorage ..> UC_Pay : <<include>>

UC_CancelBooking ..> UC_CreateBooking : <<extend>>
UC_CancelMove ..> UC_Move : <<extend>>
UC_HandleSupport ..> UC_Support : <<extend>>

@enduml
```

## Пояснение к диаграммам

### Sequence diagram

Диаграмма отражает основной сценарий оформления перемещения вещи. В ней показаны следующие участники:

| Участник | Роль |
| -------- | ---- |
| Пользователь | Инициирует перемещение вещи |
| Веб-интерфейс | Отображает данные и передаёт действия пользователя в backend |
| Бэкенд платформы | Выполняет бизнес-логику, расчёты и изменение статусов |
| Картографический сервис | Предоставляет данные карты для отображения целевых локаций |
| База данных | Хранит данные бронирований, ячеек и заказов на перемещение |
| Служба доставки | Получает запрос на назначение курьера |

Сценарий оплаты вынесен за рамки диаграммы, так как платёжный процесс описывается отдельно через интеграцию с платёжной платформой.

### Use Case diagram

Use Case-диаграмма отражает основные действия акторов в системе. В неё включены сценарии пользователя, курьера и сотрудника поддержки.

Основные сценарии пользователя:

- поиск доступной ячейки;
- создание бронирования;
- начало хранения;
- продление хранения;
- заказ перемещения вещей;
- оплата услуг;
- отслеживание статуса перемещения;
- завершение хранения;
- отмена бронирования;
- отмена заказа на перемещение;
- обращение в службу поддержки.

Основные сценарии курьера:

- получение задания на перемещение;
- подтверждение забора и доставки вещи.

Основной сценарий сотрудника поддержки:

- обработка обращения пользователя.
