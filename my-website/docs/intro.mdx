**Платформа городской сети камер хранения** – информационная система для управления хранением вещей в подключённых городских локациях и оформления перемещения вещей между ними.

Пользователь может найти подходящую локацию, выбрать доступную ячейку, оформить бронирование, оплатить услугу, отслеживать статусы хранения и при необходимости заказать перемещение вещи в другую локацию.

Физические операции – помещение вещи в ячейку, изъятие, перевозка и обслуживание оборудования – выполняются вне ядра информационной системы. При этом система сопровождает эти процессы цифрово: через статусы, данные, API и интеграции.

## Основные функции

- **Поиск локаций и ячеек** – отображение доступных вариантов хранения с фильтрацией по размеру ячейки и сортировкой по стоимости.
- **Бронирование хранения** – создание бронирования, расчёт стоимости и контрольная проверка доступности ячейки.
- **Активное хранение** – просмотр текущего хранения, статуса, плановой даты окончания и истории изменений.
- **Продление хранения** – расчёт доплаты и изменение плановой даты окончания хранения.
- **Перемещение вещи** – оформление заказа на доставку вещи из текущей ячейки в целевую локацию.
- **Оплата услуг** – создание внутреннего платежа и взаимодействие с внешней платёжной платформой.
- **Поддержка** – создание обращений, связанных с бронированием, перемещением или общей проблемой пользователя.

## Характеристики MVP

| Параметр | Значение |
| -------- | -------- |
| Масштаб запуска | Один пилотный город |
| Количество локаций | 20-50 |
| Интерфейс | Веб-платформа |
| Основные сценарии | Хранение и перемещение вещей |
| Оплата | Онлайн-оплата через внешнюю платёжную платформу |
| Поддержка | Система обращений |
| Логистика | Партнёрская |
| Real-time tracking курьера | Не входит в MVP |
| Сложная оптимизация маршрутов | Не входит в MVP |

:::tip Граница MVP
Перемещение вещей входит в MVP, потому что это одна из ключевых ценностей продукта. При этом система не управляет внутренней работой курьеров, а только сопровождает процесс через статусы и интеграции.
:::

## Границы системы

### Внутри информационной системы

- поиск и отображение доступных вариантов хранения;
- создание бронирования;
- фиксация начала и завершения хранения;
- продление хранения;
- оформление заказа на перемещение;
- расчёт стоимости;
- создание платежей;
- просмотр статусов;
- создание обращений в поддержку;
- интеграции с внешними сервисами и оборудованием.

### Вне ядра системы

- физическое помещение вещи в ячейку;
- физическое изъятие вещи;
- физическая перевозка между локациями;
- техническое обслуживание оборудования;
- внутренняя организация работы курьеров;
- юридическое урегулирование спорных случаев;
- физическая инфраструктура.

## Основные сущности

| Сущность | Назначение |
| -------- | ---------- |
| `User` | Пользователь системы |
| `Location` | Подключённая локация с камерами хранения |
| `Cell` | Ячейка хранения |
| `Booking` | Бронирование и жизненный цикл хранения |
| `Transfer` | Заказ на перемещение вещи между локациями |
| `Payment` | Платёж по бронированию, продлению или перемещению |
| `SupportRequest` | Обращение пользователя в поддержку |

## Операционные ориентиры

| Метрика | Целевое значение для MVP |
| ------- | ------------------------ |
| Время ответа API для основных операций | До 1 секунды при обычной нагрузке |
| Доступность веб-интерфейса | Достаточная для пилотной эксплуатации |
| Количество локаций | 20-50 |
| Количество ячеек | 300-1250 |

| Количество перемещений | 1-4 тыс. в год |
