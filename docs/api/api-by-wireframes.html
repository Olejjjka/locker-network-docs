Проектирование API по макетам

В рамках артефакта была подготовлена схема экранов пользовательской части платформы и определены API-источники данных, необходимые для реализации каждого экрана.

Макеты экранов охватывают пользовательскую часть системы: выбор локации, оформление бронирования, управление активным хранением, продление, оформление перемещения, просмотр заказа на перемещение и обращение в поддержку.

к сведению

Диаграмма Use Case не дублируется на этой странице, так как она уже вынесена в отдельный раздел UML-диаграммы. В данном артефакте она используется только как основание для выбора пользовательских сценариев, по которым проектировались экраны и API.

Макеты экранов системы​

примечание

Описание экранов​

1. Экран выбора локации для хранения​

Маршрут: /locations

Описание:

Экран выбора локации для хранения является основной точкой входа в пользовательский сценарий бронирования. На нём пользователь может найти доступные локации, ознакомиться с их расположением на карте и выбрать подходящую локацию для дальнейшего оформления бронирования.

Элементы:

  • поле поиска локации – позволяет искать локации по названию или адресу;
  • кнопка «Найти» – запускает поиск по введённому запросу;
  • блок фильтров / сортировки – позволяет уточнить список отображаемых вариантов;
  • список доступных вариантов хранения – содержит карточки локаций с краткой информацией;
  • карта локаций – показывает расположение доступных локаций;
  • нижнее меню навигации – содержит переходы к основным разделам приложения.

Взаимодействия:

  • нажатие на кнопку «Найти» обновляет список доступных вариантов хранения и карту локаций;
  • нажатие на кнопку «Выбрать» в карточке выбранного варианта переводит пользователя к экрану оформления бронирования;
  • нажатие на пункт «Мои хранения» в нижнем меню переводит пользователя на экран списка хранений;
  • нажатие на пункт «Поддержка» в нижнем меню переводит пользователя на экран поддержки.

Источники данных:

  • GET /api/v1/locations?search=... – поиск локаций по запросу;
  • GET /api/v1/locations/map-points?search=... – получение точек локаций на карте по поисковому запросу;
  • GET /api/v1/locations – получение списка доступных вариантов хранения;
  • GET /api/v1/locations/map-points – получение точек локаций для отображения на карте.

Для отображения карты локаций используется интеграция с внешним картографическим сервисом.

2. Экран оформления бронирования​

Маршрут: /bookings/new?locationId={locationId}

Описание:

Экран оформления бронирования предназначен для подтверждения выбранной локации, выбора размера ячейки, задания параметров бронирования, расчёта стоимости и последующего оформления и оплаты услуги хранения.

Элементы:

  • блок информации о локации – отображает название локации, адрес и режим работы;
  • блок выбора размера ячейки – позволяет выбрать подходящий размер ячейки из доступных вариантов;
  • блок параметров бронирования – позволяет выбрать дату начала и длительность хранения;
  • кнопка «Рассчитать стоимость» – инициирует расчёт стоимости хранения;
  • блок результата расчёта – отображает период хранения и стоимость;
  • кнопка «Подтвердить и оплатить» – завершает оформление бронирования;
  • кнопка «Вернуться к выбору» – возвращает пользователя на предыдущий экран;
  • нижнее меню навигации.

Взаимодействия:

  • пользователь выбирает размер ячейки, дату начала и длительность хранения;
  • нажатие на кнопку «Рассчитать стоимость» отображает стоимость хранения;
  • нажатие на кнопку «Подтвердить и оплатить» инициирует проверку доступности ячейки, создание бронирования и оплату;
  • нажатие на кнопку «Вернуться к выбору» возвращает пользователя на экран выбора локации для хранения.

Источники данных:

  • GET /api/v1/locations/{locationId} – получение данных о выбранной локации;
  • GET /api/v1/locations/{locationId}/available-cell-sizes – получение доступных размеров ячеек и соответствующих тарифов;
  • POST /api/v1/bookings/calculate – расчёт стоимости бронирования;
  • POST /api/v1/locations/{locationId}/cell-availability-check – контрольная проверка доступности подходящей ячейки перед подтверждением;
  • POST /api/v1/bookings – создание нового бронирования;
  • POST /api/v1/payments – оплата бронирования.

3. Экран «Мои хранения»​

Маршрут: /bookings

Описание:

Экран «Мои хранения» предназначен для просмотра всех бронирований пользователя. Он служит удобной точкой доступа к конкретным хранениям и позволяет пользователю открыть нужное хранение для дальнейшей работы с ним.

Элементы:

  • список хранений – отображает все бронирования пользователя в хронологическом порядке;
  • карточка хранения – содержит краткую информацию о бронировании;
  • кнопка «Открыть» – открывает выбранное хранение;
  • нижнее меню навигации.

Взаимодействия:

  • пользователь просматривает список своих хранений;
  • нажатие на кнопку «Открыть» переводит пользователя на экран активного хранения;
  • нажатие на пункт «Главная» в нижнем меню переводит пользователя на экран выбора локации для хранения.

Источники данных:

  • GET /api/v1/bookings – получение списка всех хранений пользователя.

4. Экран активного хранения​

Маршрут: /bookings/{bookingId}

Описание:

Экран активного хранения является основным экраном управления текущим хранением. На нём пользователь может просматривать информацию о бронировании, историю статусов, продлевать хранение, оформлять перемещение, завершать хранение, переходить к заказу на перемещение и обращаться в поддержку.

Элементы:

  • блок информации о бронировании – содержит основные данные о хранении;
  • блок активного перемещения – отображается при наличии активного заказа на перемещение;
  • блок истории статусов – показывает основные изменения статуса хранения;
  • кнопка «Продлить хранение»;
  • кнопка «Оформить перемещение»;
  • кнопка «Завершить хранение»;
  • кнопка «Поддержка»;
  • нижнее меню навигации.

Взаимодействия:

  • нажатие на кнопку «Продлить хранение» открывает модальное окно продления хранения;
  • нажатие на кнопку «Оформить перемещение» переводит пользователя к экрану выбора целевой локации для перемещения;
  • нажатие на кнопку «Завершить хранение» инициирует завершение текущего хранения;
  • нажатие на кнопку «Поддержка» открывает экран поддержки в контексте данного бронирования;
  • при наличии активного перемещения пользователь может нажать «Открыть заказ» и перейти к экрану заказа на перемещение.

Источники данных:

  • GET /api/v1/bookings/{bookingId} – получение информации о бронировании и связанных с ним данных;
  • GET /api/v1/bookings/{bookingId}/status-history – получение истории статусов хранения;
  • GET /api/v1/bookings/{bookingId}/can-transfer – проверка возможности оформления перемещения;
  • PATCH /api/v1/bookings/{bookingId} – завершение хранения.

4.1. Модальное окно продления хранения​

Контекст: открывается из экрана активного хранения /bookings/{bookingId}

Описание:

Модальное окно продления хранения позволяет пользователю выбрать дополнительный срок хранения, рассчитать доплату и подтвердить продление текущего хранения без перехода на отдельный экран.

Элементы:

  • блок параметров продления – отображает текущую дату окончания хранения и позволяет выбрать дополнительный срок;
  • кнопка «Рассчитать доплату»;
  • блок результата расчёта – отображает новый период хранения и сумму доплаты;
  • кнопка «Подтвердить и оплатить продление»;
  • кнопка «Отмена».

Взаимодействия:

  • пользователь выбирает дополнительный срок хранения;
  • нажатие на кнопку «Рассчитать доплату» показывает сумму доплаты и обновлённый период хранения;
  • нажатие на кнопку «Подтвердить и оплатить продление» инициирует сценарий продления хранения и оплату доплаты;
  • фактическое применение продления происходит после успешной оплаты;
  • нажатие на кнопку «Отмена» закрывает модальное окно.

Источники данных:

  • POST /api/v1/bookings/{bookingId}/extend/calculate – расчёт доплаты за продление;
  • POST /api/v1/bookings/{bookingId}/extend – инициация продления хранения;
  • POST /api/v1/payments – оплата продления.

5. Экран выбора целевой локации для перемещения​

Маршрут: /bookings/{bookingId}/transfers

Описание:

Экран выбора целевой локации для перемещения используется для выбора нового места хранения вещи в рамках уже существующего активного хранения. На нём пользователь ищет допустимые целевые локации, знакомится с их расположением на карте и выбирает подходящую локацию для дальнейшего оформления перемещения.

Элементы:

  • блок исходного хранения – отображает исходную локацию, исходную ячейку и текущий статус хранения;
  • поле поиска целевой локации;
  • кнопка «Найти»;
  • блок фильтров / сортировки;
  • список доступных вариантов перемещения;
  • карта целевых локаций;
  • нижнее меню навигации.

Взаимодействия:

  • пользователь вводит запрос в поле поиска и нажимает «Найти», после чего обновляются список доступных вариантов и карта;
  • нажатие на кнопку «Выбрать» в карточке выбранной целевой локации переводит пользователя к экрану оформления перемещения.

Источники данных:

  • GET /api/v1/bookings/{bookingId} – получение информации об исходном хранении;
  • GET /api/v1/bookings/{bookingId}/transfer-destinations?search=... – поиск допустимых целевых вариантов перемещения;
  • GET /api/v1/bookings/{bookingId}/transfer-destinations/map-points?search=... – получение точек целевых локаций на карте с учётом поиска;
  • GET /api/v1/bookings/{bookingId}/transfer-destinations – получение списка допустимых вариантов перемещения;
  • GET /api/v1/bookings/{bookingId}/transfer-destinations/map-points – получение точек целевых локаций для карты.

Для отображения карты целевых локаций используется интеграция с внешним картографическим сервисом.

6. Экран оформления перемещения​

Маршрут: /bookings/{bookingId}/transfers/new?locationId={locationId}

Описание:

Экран оформления перемещения предназначен для подтверждения выбранной целевой локации, отображения условий хранения после перемещения, расчёта стоимости и оформления заказа на перемещение с последующей оплатой.

Элементы:

  • блок информации о целевой локации;
  • блок условий хранения после перемещения;
  • блок результата расчёта;
  • кнопка «Подтвердить и оплатить»;
  • кнопка «Вернуться к выбору варианта»;
  • нижнее меню навигации.

Взаимодействия:

  • при открытии экрана система автоматически определяет требуемый размер ячейки на основе активного хранения и рассчитывает стоимость перемещения;
  • нажатие на кнопку «Подтвердить и оплатить» инициирует повторную проверку допустимости перемещения, повторную проверку доступности подходящей ячейки в выбранной целевой локации, создание заказа на перемещение и оплату;
  • нажатие на кнопку «Вернуться к выбору» возвращает пользователя к экрану выбора целевой локации для перемещения.

Источники данных:

  • GET /api/v1/locations/{locationId} – получение информации о выбранной целевой локации;
  • GET /api/v1/bookings/{bookingId} – получение информации о текущем хранении и параметрах, необходимых для подбора подходящей ячейки после перемещения;
  • POST /api/v1/bookings/{bookingId}/transfers/calculate – расчёт стоимости перемещения;
  • GET /api/v1/bookings/{bookingId}/can-transfer – повторная проверка допустимости перемещения;
  • POST /api/v1/locations/{locationId}/cell-availability-check – повторная проверка доступности подходящей ячейки в выбранной целевой локации;
  • POST /api/v1/bookings/{bookingId}/transfers – создание заказа на перемещение;
  • POST /api/v1/payments – оплата перемещения.

7. Экран заказа на перемещение​

Маршрут: /transfers/{transferId}

Описание:

Экран заказа на перемещение предназначен для сопровождения уже созданного заказа на перемещение. На нём пользователь может просматривать текущий статус заказа, маршрут перемещения, историю статусов, отменить заказ в допустимых статусах и обратиться в поддержку.

Элементы:

  • блок информации о заказе;
  • блок маршрута перемещения;
  • блок истории статусов;
  • кнопка «Отменить заказ»;
  • кнопка «Поддержка»;
  • нижнее меню навигации.

Взаимодействия:

  • пользователь просматривает текущий статус заказа и историю его выполнения;
  • нажатие на кнопку «Отменить заказ» инициирует отмену заказа на перемещение, если текущий статус это допускает;
  • нажатие на кнопку «Поддержка» открывает экран поддержки в контексте данного заказа на перемещение.

Источники данных:

  • GET /api/v1/transfers/{transferId} – получение информации о заказе на перемещение;
  • GET /api/v1/transfers/{transferId}/status-history – получение истории статусов заказа;
  • PATCH /api/v1/transfers/{transferId} – отмена заказа на перемещение.

8. Экран поддержки​

Маршруты:

  • /support
  • /support?bookingId={bookingId}
  • /support?transferId={transferId}

Описание:

Экран поддержки служит единым центром работы с обращениями пользователя. На нём можно создать новое обращение, просмотреть список ранее созданных обращений и при необходимости сформировать обращение в контексте конкретного бронирования или заказа на перемещение.

Элементы:

  • блок связанного объекта, если есть;
  • форма создания обращения;
  • кнопка «Отправить обращение»;
  • список обращений;
  • нижнее меню навигации.

Взаимодействия:

  • пользователь заполняет форму и отправляет новое обращение;
  • при открытии экрана из контекста хранения или перемещения отображается информация о связанном объекте;
  • пользователь может просматривать список своих предыдущих обращений.

Источники данных:

  • GET /api/v1/bookings/{bookingId} – получение данных связанного бронирования при открытии экрана поддержки из контекста хранения;
  • GET /api/v1/transfers/{transferId} – получение данных связанного заказа на перемещение при открытии экрана поддержки из контекста перемещения;
  • GET /api/v1/support-requests – получение списка обращений пользователя;
  • POST /api/v1/support-requests – создание нового обращения.

Спецификация OpenAPI​

В рамках задания была разработана спецификация OpenAPI для пользовательской части платформы городской сети камер хранения.

Спецификация построена на основе макетов экранов и описывает источники данных, необходимые frontend-части для реализации пользовательских сценариев. В спецификации определены основные endpoints, параметры запросов, модели запросов и ответов.

Интерактивная версия спецификации доступна в разделе OpenAPI.
